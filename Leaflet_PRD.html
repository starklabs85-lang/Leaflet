Section 01

Overview & the problem worth solving

Leaflet is a mobile app for home plant-parents — not field botanists. The MVP validates one core loop: scan → understand → add to my collection → keep it alive. Social features, marketplaces and human experts are deliberately deferred until that loop proves it retains users.

The problem

  • New owners can't reliably name what they have, so they can't look up the right care.
  • When a plant looks sick, people guess (and usually over-water) — the single biggest reason they quit the hobby.
  • Generic reminders ignore the species and the season, so they get dismissed and ignored.
  • Tracking lives in notes apps, memory and spreadsheets — fragmented and quickly abandoned.

✓ Goals (MVP)

  • Identify a plant from a photo with a confidence indication.
  • Surface clear, structured care info per species.
  • Diagnose common diseases & pests from a photo with a treatment plan.
  • Save plants to a personal collection and track care metrics.
  • Present an attractive, at-a-glance health dashboard.

✕ Non-Goals (deferred)

  • Social feed, community Q&A, or sharing.
  • Live human expert consultations.
  • Plant or supply marketplace.
  • Insect / bird / mushroom / weed ID — plants & disease only.
  • Offline on-device identification.

Section 05

The five MVP features

Feature 01

📷 Scan & Identify

  • In-app camera or photo-library upload.
  • Capture-guidance overlay for a clear leaf / flower / whole-plant shot.
  • OpenAI vision returns the most likely species + 2–4 alternates.
  • Each result shows confidence, common & scientific name, thumbnail.
  • Confirm the match to open the plant detail page.
Feature 02

📖 Plant Information

  • Structured species profile with description & hero image.
  • Care basics: light, water, soil, humidity, temperature, feeding.
  • Toxicity flag for pets & children — high-value safety signal.
  • Difficulty rating (easy / moderate / hard) to set expectations.
Feature 03

🩺 Disease & Pest Diagnosis

  • Separate "Diagnose" scan mode for an unhealthy plant.
  • Returns most likely condition with a confidence level.
  • What it is · likely cause · step-by-step treatment · prevention.
  • Attach the diagnosis to a tracked plant + set a follow-up reminder.
Feature 04

🪴 Collection & Tracking

  • Save plants with a nickname & room/location tag.
  • Care schedule auto-generated from species data, fully editable.
  • Quick-log: watered, fertilized, repotted, pruned, noted an issue.
  • Metrics: watering history, growth photos, health status, streaks.
  • Local notifications for due care tasks.
Feature 05

📊 The Dashboard

  • Home screen: today's tasks, plants needing attention, overall collection health.
  • Visual plant cards with photo, nickname, next task and a health indicator.
  • Simple charts — watering consistency over time and a per-plant growth timeline.
  • A streak / completion stat to build habit and drive retention.

Section 07

How it fits together (Expo · Supabase · OpenAI)

An Expo (SDK 55) React Native app talks to Supabase for everything backend: Auth (Apple & Google providers), Postgres for the collection and care data, Storage for plant photos, and Edge Functions as the secure relay to the OpenAI vision API. The OpenAI key never touches the device — the Edge Function holds it, sends the photo plus a task-specific prompt, validates the JSON, and caches results. Identification and diagnosis share that one pipeline.

System architecture — Expo client, Supabase platform, OpenAI vision

Why this shape matters for the build

The Edge Function is the trust boundary. Routing OpenAI through Supabase Edge Functions keeps the API key server-side, lets you validate and cache responses, and enforces per-user rate limits in one place. Pair it with row-level security in Postgres so each user only sees their own plants. Because one general model does both ID and diagnosis, accuracy hinges on prompt design and image quality — always show a confidence level, offer alternates, and treat diagnosis as advisory.

Section 08

Tech stack

A deliberately lean, managed stack — Expo for the client, Supabase for the entire backend, OpenAI for vision. Minimal infrastructure to own, which keeps a solo/small team moving fast on the MVP.

Client

📱 Expo (SDK 55)

  • React Native via Expo for iOS-first, cross-platform-ready development.
  • Expo Camera / Image Picker for capture and library upload.
  • Expo Notifications for local care reminders.
  • EAS Build & Submit for store delivery and OTA updates.
Auth

🔐 Sign in with Apple & Google

  • Native Apple & Google sign-in wired into Supabase Auth (OAuth providers).
  • Sign in with Apple is required by App Store policy when offering Google — both included.
  • Sessions persisted securely on-device; auth gates cloud sync.
Backend

⚡ Supabase

  • Postgres — collection, care tasks, logs, diagnoses; row-level security per user.
  • Storage — plant photos and growth-timeline images.
  • Edge Functions — secure OpenAI relay, JSON validation, caching, rate limiting.
  • Realtime (optional) — keep the dashboard live across a user's devices.
Vision

🤖 OpenAI API

  • Vision model for both species ID and disease/pest diagnosis.
  • Prompted for structured JSON with a confidence field and ranked alternates.
  • Called only from a Supabase Edge Function — key never ships in the app.

Two stack decisions to lock early

1 · Apple sign-in is mandatory if you ship Google sign-in on iOS — App Store review requires it, so both are in the MVP, not optional. 2 · Confirm the Expo SDK version against the latest release at build time and check that your camera, notifications and auth libraries are compatible with that SDK before locking it in.

Non-functional requirements

  • Performance — identification result in under ~5 seconds on a normal connection.
  • Reliability — graceful handling of low-confidence or failed scans with retry guidance.
  • Privacy & security — clear camera/photo consent; photos transit to OpenAI via the Edge Function (disclose this); Supabase row-level security so users only access their own data; published privacy policy.
  • Platforms — iOS first (or cross-platform via a shared framework), phone form factor.
  • Accessibility — legible type, strong contrast, support for system text scaling.
  • Cost control — cache species/care data and debounce scans to manage per-call API spend.

Section 11

Dependencies, assumptions & risks

🔗 Dependencies & assumptions

  • OpenAI API (vision) for both ID and diagnosis — no custom model in the MVP.
  • Supabase for auth, Postgres, storage and Edge Functions.
  • Apple & Google developer accounts + OAuth credentials configured.
  • Licensed or sourced species/care content for the supported plant set.
  • Users will grant camera & notification permissions.

⚠️ Risks & mitigations

  • ID accuracy varies by species & photo → always show confidence, offer alternates & retry.
  • API cost scales with usage → cache results in Supabase, debounce, monitor per-user volume.
  • Diagnosis is advisory, not authoritative → clear disclaimer; never present as certain.
  • Apple review rejects Google-only sign-in → ship Sign in with Apple alongside it.
  • Crowded market → win on free-tier generosity, UI quality & tracking depth.
